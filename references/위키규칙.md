# 위키 규칙

`SKILL.md` 가 STEP 7·8 에서 연다. 문서를 짓기 시작할 때 한 번 읽고, 막히면 다시 온다.

`louiswang524/llm-knowledge-base` (MIT) 의 위키 구조와
`kb-reflect` · `kb-lint` · `kb-ask` 설계를 바탕으로 고쳐 썼다.

---

## 1. 위키 문서 한 장은 무엇인가

**질문 하나에 온전히 답하는 크기다.** 장수를 미리 정하지 않는다.

| 이렇게 판정한다 | |
|---|---|
| 질문 **하나**에 답하고 재료가 **둘 이상** 붙는다 | 맞는 크기다 |
| 재료가 **하나**뿐이고 얇다 | 위 문서 안으로 넣는다. 한 장으로 안 세운다 |
| 질문이 **여럿** 섞여 있다 | 쪼갠다 |

주소 하나에 주제 하나가 원칙이다. 한 장에 주제를 셋 넣으면 셋 다 어중간하게 걸리고,
한 장에 재료를 하나만 넣으면 얇아서 감점된다.

### 제목은 재명명된 이름으로 짓는다

**이게 이 단계의 핵심이다.** 02 `근거.md` 의 재명명 표에서 오른쪽 칸을 가져온다.

```
✕  AI 툴 평가 기준 마련          본인이 쓴 말. 그 업계 언어가 아니다
○  모델·툴 평가 프레임워크 설계   가려는 자리에서 쓰는 말
```

**이건 예시일 뿐이다.** 실제 짝은 그 사람의 `근거.md` 재명명 표에 있다.
표가 비어 있으면 **여기서 지어내지 않는다.** 02 로 되돌려 보낸다.

재료에 없는 일을 있는 것처럼 부르지 않는다. **사실은 그대로 두고 이름만 바꾼다.**

## 2. 문서 양식

**아래는 지어낸 예시다.** 실제 사람의 자료가 아니다. 모양만 보면 된다.

```markdown
---
허브: 같은 일 하는 사람
클러스터: 도구 고르기
질문: 새 도구를 쓸지 말지 뭘 보고 정하나
---

# 도구 도입 판정 기준 설계

한 일과 판단을 그대로 쓴다. 잘 보이게 다듬지 않는다.
「무엇을 · 어떻게 · 그래서 뭐가 바뀌었나」 셋이 채워지면 충분하다.
안 채워지는 칸은 비운다. 지어내지 않는다.

## 어디서 나왔나

| 재료 | 앵커 | 형식 | 날짜 |
|---|---|---|---|
| [도구 비교 보고서](../../raw/pdfs/도구-비교-보고서-a1b2c3.md) | `네 개 축으로 점수를 매겨` | pdf | 2024 |
| [3주차 회고](../../raw/notes/3주차-회고-d4e5f6.md) | `한계까지 적어두고 판정했다` | note | |

## 이어지는 것

[요청 양식 재설계](요청-양식-재설계.md)
[원본 불변 데이터 설계](원본-불변-데이터-설계.md)
```

제목 · 허브 · 클러스터 · 질문은 **그 사람의 02 산출물에서 나온다.**
이 예시의 말을 그대로 쓰지 않는다.

### 머리말 세 줄은 비우지 않는다

| | |
|---|---|
| `허브` | 비면 `lint.py` 가 **고아**로 짚는다. 허브가 정해지기 전에 문서를 쓰지 않는다 |
| `클러스터` | 허브 안의 갈래 |
| `질문` | 이 문서가 답하는 질문 하나. **이게 나중에 「목표 질문」 목록이 된다** |

`질문` 칸이 문서를 만들 때 채워지므로 **고아 질문이 애초에 안 생긴다.**
질문을 먼저 만들고 답할 재료를 찾는 게 아니라, 문서가 서고 거기서 질문이 나온다.

## 3. 링크 규칙

**대괄호 위키 링크(`[[이름]]`)를 쓰지 않는다.** 옵시디언에서만 열린다.
상대경로 마크다운 링크는 옵시디언 · 깃허브 · 06 이 지을 사이트에서 다 열린다.

| 어디로 | 어떻게 |
|---|---|
| 다른 개념 문서 | `[제목](파일이름.md)` · 같은 폴더 |
| 재료 | `[이름](../../raw/notes/xxx.md)` · **작업폴더 상대경로** |
| 목차 | `[제목](concepts/파일이름.md)` · `index.md` 에서 |

### 절대경로를 절대 안 적는다

사용자 이름이 박혀 있다. 위키는 06 을 거쳐 발행되므로 그대로 새어 나간다.
02 가 `근거.md` 에서 이미 잡아둔 규칙이고 03 도 같다.

### 앵커는 줄 번호가 아니라 원문 조각이다

백틱 안에 원문 12~30자를 넣는다. 재변환해도 안 어긋나고 `grep` 으로 다시 찾을 수 있다.
**대괄호가 든 이름은 링크 글자에 넣지 않는다.** `[[회사명] 이력서](...)` 는 링크가 안 열린다.

### 파일 이름

제목을 소문자로 낮추고 띄어쓰기와 가운뎃점을 하이픈으로 바꾼다. 한글은 그대로 둔다.

```
모델·툴 평가 프레임워크 설계   →   모델-툴-평가-프레임워크-설계.md
```

## 4. 빠진 연결 찾기 (`kb-reflect` 설계)

문서를 다 쓴 뒤에 한다. **2단으로 돈다.** 02 의 4단 읽기와 같은 모양이다.

| 단 | 무엇 | 값 |
|---|---|---|
| 1단 | `index.md` 의 한 줄 요약만 보고 볼 자리를 고른다 | 싸다 |
| 2단 | 고른 자리마다 관련 문서를 열어 깊게 읽는다 | 비싸다 |

**개수를 안 정한다.** kb-reflect 는 후보를 3~5개로 박아뒀는데 그 자리를 푼다.
01·02 가 이미 개수를 안 박아온 규칙과 같다.

찾는 것 넷.

| | 무엇 | 왜 값어치가 있나 |
|---|---|---|
| 걸쳐 있는 것 | 서로 다른 출처에 되풀이되는 주제 | 클러스터 후보다 |
| 이어야 할 것 | 깊이 관련 있는데 링크가 없는 두 문서 | 「이어지는 것」에 넣는다 |
| 어긋난 것 | 같은 주제에 반대로 적힌 두 문서 | 어느 쪽이 나중 판단인지 날짜로 본다 |
| **비어 있는 것** | 여러 곳이 가리키는데 정작 문서가 없는 주제 | ★ **07 의 글감 목록이 여기서 나온다** |

**증거가 약하면 문서를 안 쓰고 「찾았지만 안 씀」으로 기록한다.**
02 의 「지어내지 않는다」와 같은 말이다.

## 5. 검사 읽는 법 (`kb-lint` 설계)

```bash
python3 "{이 스킬이 설치된 폴더}/scripts/lint.py" "{작업폴더}"
```

| 짚힌 것 | 어떻게 한다 |
|---|---|
| `A` 본문이 얇다 | 재료를 더 붙이거나 위 문서 안으로 합친다. **표는 본문으로 안 센다** |
| `B` 링크는 걸렸는데 문서가 없다 | 그 문서를 만들거나 링크를 뺀다 |
| `C` 링크가 안 열린다 | 경로를 고친다. **한글 경로면 NFC 를 의심한다** |
| `D` 두 문서가 겹쳐 보인다 | 하나로 합치고 링크를 다 고친다 |
| `F` 고아 | `허브` 를 채우거나 `index.md` 에 올린다 |
| `G` 근거가 없다 | 재료 출처를 붙인다. **못 붙이면 그 문서를 지운다** |
| `H` 본문 없는 재료에서만 만들었다 | 그 문서를 지운다. 이미지면 먼저 본문을 채운다 |
| `I` 개인정보 | ★ **아래** |

### `I` 가 나오면 멈춘다

**위키에 한 번 들어간 연락처는 그대로 공개된다.** 02 는 근거를 뽑을 뿐이지만
03 은 문서를 새로 쓰고 그게 06 에서 사이트가 되고 07 이 발행한다.

| | |
|---|---|
| 1 | 02 `근거.md` 의 「개인정보」 절을 먼저 본다. **02 가 이미 판정한 자리는 다시 안 묻는다** |
| 2 | 02 가 「실습용 가상 데이터」로 판정한 것이면 그대로 쓴다. 이유를 문서에 한 줄 적는다 |
| 3 | 02 가 안 본 자리이고 실제 값이면 ★ **가린다. 재료를 빼지 않는다** |
| 4 | 값은 화면에도 문서에도 기록에도 안 옮긴다. **경로와 종류만** |

### 빼는 게 아니라 가린다

**위키에서만 빼면 값이 재료에 그대로 남는다.** 재료는 06 도 07 도 읽는다.

```
1  재료 md 본문의 값을 [가림] 으로 바꾼다      문장은 남기고 값만 지운다
2  머리말에 sensitive: {종류} · masked_at: {날짜}   값은 안 적는다
3  .kb/manifest.json 에도 같은 줄
4  원본 파일은 절대 안 건드린다
5  재료는 살린다. 위키에도 그대로 쓴다
```

**「안 씀 · 개인정보」로 내리는 건 가릴 수 없을 때만이다.**
문장 전체가 개인정보라 값을 빼면 남는 게 없을 때, 그리고 **이미지**다.
이미지는 값을 가릴 수가 없다.

**웹 검색으로 문서를 채우는 검사(`kb-lint` 의 `E2`)는 통째로 뺐다.**
남의 문장이 근거 옆에 붙으면 그게 곧 지어내기다.

## 6. 질문에 답할 재료가 있나 (`kb-ask` 설계)

보드가 「`kb-ask` 로 실제 답이 나오나」를 통과 조건으로 걸어놨다.
**색인을 안 쓰고 `grep` 으로 한다.**

`kb_search.py` 의 토크나이저가 `[a-z0-9]+` 라 한글이 한 글자도 안 남는다.
그 위의 점수가 한글 질문에 전부 0이 된다. 그리고 파이썬 패키지 설치를 요구한다.
**개발자가 아닌 사람에게 이 체인에서 제일 잘 막히는 자리다.**

```bash
grep -rn "{질문에서 뽑은 말}" {작업폴더}/wiki/concepts/
grep -rn "{질문에서 뽑은 말}" {작업폴더}/raw/
```

**NFC 를 맞추고 나서 찾는다.** 안 맞추면 한글이 든 경로에서 아무것도 안 걸린다.
`grep -c` 가 0인데 `ls` 로는 그 경로가 보이면 이 문제다.

질문마다 답할 문서가 실제로 걸리는지 확인한다. **안 걸리면 그 질문을 뺀다.**
문서가 먼저 서고 거기서 질문이 나왔으므로 이 검사는 대개 통과한다.
통과 못 하면 문서를 안 보고 질문을 만든 것이다.

## 7. 안 쓰는 것

| kb 스킬 | 왜 안 쓰나 |
|---|---|
| `kb-compile` | **절차를 통째로 못 쓴다.** 출처마다 요약 1장을 만드는데, 그건 그 재료보다 정보가 적다. 세 층 구조만 가져왔다 |
| `kb-merge` | 중복은 앞에서 이미 잡았다. 본문 해시로 묶어 대표 하나만 센다 |
| `kb_search.py` | 한글이 통째로 버려진다. `grep` 으로 간다 |
| `kb-lint` 의 `E2` | 웹 검색 결과를 문서에 붙인다. 지어내기가 된다 |

**한 개도 설치하지 않는다.** 다섯 스킬이 전부 첫 단계가 `cat ~/.claude/kb-config.json`
인데 그 파일이 없다. 이 체인은 `iny-config.json` 을 쓴다. 되돌리면 kb 를 같이 쓰는 사람과 부딪힌다.
