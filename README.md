# iny-structure

**흩어진 자료를 남이 궁금해하는 순서로 다시 놓는 Claude Code 스킬입니다.**

자료는 **쓴 순서**로 있습니다. 회고일지, 수행일지, 이력서, 보고서.
그런데 **남이 궁금해하는 순서는 그게 아닙니다.**

> "AI 툴 쓸지 말지 뭘 보고 정해요?"

이 하나에 답하려면 자료 **세 곳**을 뒤져야 합니다.
흩어져 있어서 아무도 못 찾습니다. 본인도요.

**여기서는 그 셋을 한자리에 모읍니다.** 자료를 옮기는 게 아니라,
자료를 가리키면서 **그 일의 이름을 붙여 놓는 것**입니다.

에셋엔진 워크플로우의 **03단계**입니다. `v1.2`

## 이게 어디에 쓰이나

한 번 만들면 뒤 단계가 그대로 받아 씁니다.

| | 여기서 만든 문서 한 장이 |
|---|---|
| 06 사이트 | 페이지 한 개가 됩니다. 주소 하나 |
| 07 글쓰기 | 글 한 편의 뼈대가 됩니다. 근거가 이미 붙어 있습니다 |
| 검색 · AI 답변 | 「이 사람은 뭘 할 줄 아나」에 꺼내 쓰는 조각이 됩니다 |

02 에서 **「지금 AI 는 나를 이렇게 말한다」**를 재두셨을 겁니다. 대개 안 나옵니다.
**여기서 만드는 문서 한 장이 나중에 그 자리 한 줄이 됩니다.**

## 자료를 전부 문서로 만들지 않습니다

자료 하나마다 요약 문서 하나를 만들면 자료가 1,000개일 때 문서가 1,000장이고,
그중 절반은 이미지와 복사본에서 나옵니다.
**그 문서는 원래 자료보다 정보가 적습니다.**

그래서 말을 넷으로 나눠 씁니다.

| | 무엇 | 몇 개까지 |
|---|---|---|
| **훑는다** | 머리말과 글자수만 봅니다 | 전량 |
| **가른다** | 컨셉 기준으로 글감 · 근거 · 안 씀으로 나눕니다 | 전량 |
| **엮는다** | 주제로 묶어 문서를 씁니다 | 글감만 |
| **안 엮는다** | 목록에는 남기고 문서로 안 만듭니다. **개수와 이유를 말합니다** | 나머지 |

**몇 장을 만들겠다고 미리 약속하지 않습니다.** 조건 셋을 걸고, 다 만든 뒤에 몇 장인지 말합니다.

| | |
|---|---|
| 1 | 모든 문서가 어느 묶음에 붙어 있다 |
| 2 | 모든 문서에 본인 자료 출처가 붙어 있다 |
| 3 | 본문 없는 자료에서 만든 문서가 0이다 |

**자료는 하나도 안 지웁니다.** 「안 씀」은 이번에 안 쓴다는 뜻입니다.

## 어려운 말을 그대로 안 씁니다

「허브」 「클러스터」 「슬러그」 같은 말은 화면에 그대로 안 나옵니다.

| 원래 말 | 화면에 나오는 말 |
|---|---|
| 허브 | **큰 갈래** |
| 클러스터 | **작은 갈래** |
| 슬러그 | **주소에 쓸 이름** |
| 고아 | **어느 갈래에도 안 붙은 문서** |

문서 파일 안에는 원래 말이 그대로 들어갑니다. **04·05·06 이 그 이름으로 읽기 때문입니다.**
바뀌는 건 화면에 내는 말뿐입니다.

---

## 손일을 넘기지 않습니다

자료가 수백 개일 때 그걸 하나씩 판정하는 화면을 만들지 않습니다.

| | 누가 | 무엇 |
|---|---|---|
| 가른다 | **스킬** | 컨셉 기준으로 전부 갈라 놓습니다. 안 씀에는 이유를 적습니다 |
| 짚는다 | **사람** | 묶음 단위 표를 보고 **「이건 아닌데」만** 말합니다 |

질문 다섯 개가 **전부 「고르기」이지 「하기」가 아닙니다.**

---

## 폴더 이름으로 주인을 안 가릅니다

학원 · 부트캠프 · 사내 교육 자료는 **강사 자료와 본인 제출물이 한 폴더에 있습니다.**
폴더 이름으로 가르면 둘이 같이 버려집니다.

> **폴더 끝의 사람 이름으로 가릅니다.**

```
데이터분석과정/3주차_실습_이강사      ← 강사가 만든 자료
데이터분석과정/7주차_팀프로젝트_민지   ← 본인이 만든 것
```

어느 이름이 본인 것인지만 한 번 알려주시면 나머지는 스킬이 가릅니다.

### 남의 폴더 안에 있는 본인 글도 살립니다

폴더 이름만 보고 통째로 빼면 **그날 본인이 쓴 회고가 같이 날아갑니다.**

```
3주차_실습_이강사/
    3주차_강의교재.pdf     ← 강사가 만든 것
    4Ls-회고-3주차.md      ← ★ 본인이 쓴 것. 폴더 이름만 보면 같이 빠집니다
    3주차_수행일지.md       ← ★ 본인이 쓴 것
```

스킬이 파일 이름과 본문을 보고 **살릴 것을 골라 놓고, 살린 목록을 보여드립니다.**
아닌 게 있으면 그때 빼시면 됩니다.

## 이미지를 자동으로 빼지 않습니다

형식이 이미지라고 「안 씀」에 넣지 않습니다.
그 안에 **직접 만드신 화면**이 섞여 있습니다.
글로만 있는 「무엇을 설계했다」에 **그림 근거를 붙이는 유일한 자료**입니다.

몇 장이 그런 것인지 세어서 보여드리고, **열어서 안에 뭐가 있는지 적을지** 여쭤봅니다.
"네" 하시면 **스킬이 엽니다.** 따로 하실 것이 없습니다.

**열기 전에 한 번 더 거릅니다.** 중복 · 아이콘 · 남이 만든 폴더 · 원본이 없는 것은 열어도 못 씁니다.
**거른 개수와 이유를 말씀드립니다.** 100장이라고 했다가 60장만 열면 왜 40장을 뺐는지 말합니다.

## 쓰는 법

작업 폴더에서 Claude Code 를 열고 이렇게 칩니다.

```
구조 잡기
```

안내문이 먼저 나오고, 그다음 질문 다섯 개가 이어집니다.

| | | |
|---|---|---|
| 1 | 02 에서 정한 컨셉을 읽습니다 | 기다리시면 됩니다 |
| 2 | 자료 묶음이 누가 만든 건지 확인 | 질문 1개 |
| 3 | **다 갈라 놓고 표로 보여드림** | ← 보시고 「이건 아닌데」만 |
| 4 | 직접 만드신 화면을 열어볼지 확인 | 질문 1개 |
| 5 | **주제를 어떻게 묶을지 후보를 드림** | 질문 1개 |
| 6 | 문서를 씁니다 | 기다리시면 됩니다 |
| 7 | **질문 · 글 목록 · 주소 규칙을 보여드림** | 질문 1개 |

중간에 멈추셔도 되고, 모르는 건 안 정하고 넘어가셔도 됩니다.
**완주해야만 문서가 나오는 게 아닙니다.**

## 나오는 것

**위키와 문서 3장**입니다.

```
wiki/
  index.md            목차. 묶음 단위로 접혀 있습니다
  concepts/           주제마다 문서 한 장

outputs/03-structure/
  plan.md             ★ 여기부터 봅니다
  구조.md
  분류.md
```

| | |
|---|---|
| `wiki/` | 주제마다 문서 한 장. **06 이 이걸로 페이지를 만듭니다** |
| `구조.md` | 주제 묶음 · 답하는 질문 · **글 목록 초안** · 주소 규칙 |
| `분류.md` | 뭘 쓰고 뭘 안 썼나. **안 쓴 것은 이유가 다 적혀 있습니다** |
| `plan.md` | 정해진 것 · 안 정해진 것 · **안 엮은 자료** · 다음에 할 일 · 04 설치 명령 |

### 문서 한 장은 질문 하나에 답하는 크기입니다

| | |
|---|---|
| 자료가 둘 이상 붙고 질문 하나에 답한다 | 맞는 크기입니다 |
| 자료가 하나뿐이고 얇다 | 위 문서 안으로 넣습니다. 한 장으로 안 세웁니다 |
| 질문이 여럿 섞여 있다 | 쪼갭니다 |

**주소 하나에 주제 하나**가 원칙입니다.
한 장에 주제를 셋 넣으면 셋 다 어중간하게 걸리고,
한 장에 자료를 하나만 넣으면 얇아서 감점됩니다.

### 사이트 구조는 03 이 정하지 않습니다

주제를 두 층으로 나눕니다. **큰 갈래** 안에 **작은 갈래**가 들어갑니다.

그런데 **이건 글을 나누는 칸이지 사이트 메뉴가 아닙니다.**

```
{글이 들어갈 자리}
    └ 큰 갈래
        └ 작은 갈래
            └ 글 한 편        ← 03 이 만든 문서 한 장
```

| | 03 이 정하나 |
|---|---|
| 글이 몇 편이고 어떻게 나뉘나 | **정합니다.** 이게 03 의 일입니다 |
| 메뉴가 몇 개고 뭐가 들어가나 | **안 정합니다.** 04 화면설계에서 직접 고르십니다 |
| 글 자리 이름과 주소 | **안 정합니다.** 후보만 냅니다. 04·05 |

포트폴리오 사이트인지 브랜드 사이트인지, 만든 것을 앞에 낼지 글을 앞에 낼지는
**만드시는 분 마음입니다.** 03 은 그 결정에 필요한 재료를 만들어 놓을 뿐입니다.

### 제목은 재명명된 이름으로 짓습니다

02 가 만든 재명명 표를 그대로 씁니다.

```
✕  AI 툴 평가 기준 마련          본인이 쓴 말
○  모델·툴 평가 프레임워크 설계   가려는 자리에서 쓰는 말
```

사실은 그대로 두고 **이름만 바꿉니다.**

### 질문은 문서에서 나옵니다

질문을 먼저 만들고 답할 자료를 찾는 게 아닙니다.
**문서가 먼저 서고 거기서 질문이 나옵니다.**

그래서 **답할 자료가 없는 질문이 애초에 안 생깁니다.**
개수를 미리 약속하지 않습니다. 문서가 서면 따라서 정해집니다.

## 알아둘 것

**개인정보는 문서를 쓰기 전에 막습니다.** 03 은 문서를 새로 쓰고,
그게 06 에서 사이트가 되고 07 이 발행합니다. **한 번 들어간 연락처는 그대로 공개됩니다.**

**다만 자료를 빼지 않고 값만 가립니다.** 자료에서 빼기만 하면 값이 자료에 그대로 남고,
그 자료는 06 도 07 도 읽습니다.

| | |
|---|---|
| 자료 본문의 값 | `[가림]` 으로 바꿉니다. 문장은 남고 값만 지워집니다 |
| 자료 맨 위 정보 칸 | 어떤 종류였는지와 가린 날짜만 적습니다. **값은 안 적습니다** |
| 원본 파일 | **절대 안 건드립니다** |
| 자료 자체 | **살립니다.** 값이 가려졌으니 문서에 쓸 수 있습니다 |

가릴 수 없을 때만 「안 씀」으로 내립니다. 문장 전체가 개인정보이거나, 이미지일 때입니다.

**남이 만든 자료는 문서로 안 엮습니다.** 강의 교재처럼 남의 저작물은 엮지 않습니다.
자료에서 빼지는 않습니다. **내가 뭘 배웠나의 흔적으로는 값이 있습니다.**

**대괄호 위키 링크(`[[이름]]`)를 안 씁니다.** 옵시디언에서만 열립니다.
상대경로 링크만 써서 옵시디언 · 깃허브 · 06 이 지을 사이트에서 다 열리게 합니다.

**절대경로를 문서에 안 적습니다.** 원본 경로에는 사용자 이름이 박혀 있습니다.

**스킬이 알아서 커밋하지 않습니다.** 뭐가 들어갔는지 모른 채 이력이 쌓이는 걸 막습니다.

**자료에 없는 것은 지어내지 않습니다.** 증거가 약하면 문서를 안 쓰고
「찾았지만 안 씀」으로 기록합니다.
